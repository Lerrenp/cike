## 一、项目概述

「此刻」是一款轻量化、纯净、高颜值、操作极简的垂直图文分享社区产品，聚焦"记录生活、分享美好、轻量种草、兴趣互动"核心场景。本训练营以此项目贯穿全栈开发全流程，最终交付一个**前后端分离、可运行、已部署至 Gitee 的完整项目**。

### 核心页面（5 大页面）
| 页面 | 作用 |
|---|---|
| 首页 | 瀑布流浏览、分类标签筛选、关键词搜索、下拉刷新/上拉加载 |
| 发布页 | 多图上传（≤9张）、标题正文编辑、话题添加、公开/仅自己可见 |
| 详情页 | 图文展示、点赞/收藏、评论回复、关注作者、相关推荐 |
| 个人中心 | 头像昵称简介、作品/收藏/点赞管理、账号设置 |
| 登录注册 | 手机号+验证码注册、手机号+密码/验证码登录、未登录拦截 |

### 技术栈
- 前端：Vue3（组合式 API）+ Vite + Element Plus + Vue Router + Pinia，适配移动端（≤768px）/平板（769–1200px）/电脑（≥1201px）
- 后端：Java + SpringBoot（Spring Initializr 脚手架）+ MySQL + Redis（缓存 token、热门笔记、计数）
- 工具：IDEA（后端开发）、DBever（数据库可视化）、Treework（AI 设计/开发）、ApiFox（接口测试）、Gitee（代码托管）

## 二、项目结构与目录规范

```

├── backend/             # 后端代码（SpringBoot 工程）
├── docs/                # 全部文档（PRD、数据库设计、API 接口文档等）
│   ├── 「此刻」图文分享社区产品需求文档（PRD）.md
│   ├── 「此刻」图文分享社区- MySQL数据库设计文档.md

│   └── seed.sql               # 种子数据脚本
└── homework/            # 每日作业（Day01~Day14 各一个文件夹）
```

**规范要求**：
1. 前端代码必须整体放入 `frontend/`（含 index.html、vite 配置文件等完整工程），禁止散落在根目录。
2. 后端代码必须放入 `backend/`，且**不在后端内部单独创建 git 仓库**，统一由 `cike` 根目录管理。
3. 后端项目通过 IDEA 使用 SpringBoot 脚手架创建，项目名与 `backend` 文件夹同名。
4. 前端 `.gitignore` 中必须忽略 `node_modules`（上传前删除该目录），避免把依赖提交进仓库。
5. 空文件夹默认不会上传 Gitee，属正常现象。

## 三、开发流程指引（课堂规范）

### 阶段 1：需求与设计（已完成）
1. 产品经理产出 PRD 需求文档（V1.0 仅五大核心页面闭环）。
2. UI/UX 设计：使用 Treework **design 模式**，将 PRD 拖入对话框，配以小红书五大页面截图，产出原型图。
3. 用 AI 根据 PRD 生成 **数据库设计文档**，再根据数据库设计文档生成 **init.sql 建表脚本**。

### 阶段 2：数据库搭建（已完成，对应 DAY06/DAY07）
1. 本地安装 MySQL，设置 root 密码为 `123456`，端口 `3306`。
2. DBever 新建连接：主机 `localhost`，端口 `3306`，用户名 `root`，密码 `123456`；高级→驱动属性中开启允许公钥连接（本地连接报错时处理）。
3. 在 DBever 的 SQL 控制台**先执行 `init.sql`** 创建数据库与全部表结构。
4. 让 AI 根据（PRD + 数据库设计文档 + init.sql）生成 **seed.sql 种子数据脚本**，控制台执行插入数据。
5. 若 seed.sql 执行出错：把报错反馈给 AI 修正；修正后需**重新执行 init.sql 再执行 seed.sql**（避免残留数据）。

### 阶段 3：后端开发（进行中，对应 DAY07）
1. 将 API 接口文档（AI 根据 PRD + 数据库设计文档 + init.sql 生成，遵循 Restful API 规范）放入 `docs/`。
2. 让 AI 根据 `docs/` 内全部文档生成完整后端代码：
   - 使用 Treework 的 `/spec` 模式（新建空白对话，输入 `/spec` 回车后粘贴提示词）
   - 配置项：数据库本地服务、端口 3306、root/123456；Redis 使用桌面解压版；JDK 使用本机已装版本（可通过 IDEA 文件→项目结构→SDK 查看路径）
3. AI 生成完成后在代码管理侧提交，预计耗时 2~3 小时。
4. 后端工程初始依赖：`spring-boot-starter-web` 与 `spring-boot-starter-test`（DAY06 演示过静态资源 + 接口调用验证链路）。

### 阶段 4：前后端联调（进行中，对应 DAY08）
- 联调基础：后端与数据库联调依据「数据库设计文档」，前端与后端联调依据「API 接口文档」。
- 接口调试工具：**ApiFox**（国产替代 Postman）。新建项目 → 分模块建目录 → 按接口文档配置请求方式（GET/POST/PUT/DELETE）、URL、请求体（JSON）、Header（登录 token）→ 发送测试。

**DAY08 用户模块全链路打通（课堂核心流程）**
1. 联调前准备（三个前提）：目录结构清晰（frontend/backend/docs 分文件夹）；后端代码完整；数据库已建表并有数据；前端 `npm run dev` 可正常访问。
2. 启动依赖服务：先启动 Redis（桌面 redis → 运行 `start.bat`，端口 6379，`application.properties` 中已配置）；再用 IDEA 启动 SpringBoot（端口 8080）。
3. **后端↔数据库联调（用 ApiFox 测接口）**：
   - 配置前置 URL 为后端基础地址（`http://localhost:8080`，注意接口文档中若基础地址带 `/api/v1` 需一并加上）。
   - 逐条测试用户相关接口：发送短信验证码、注册、登录、查询用户列表、查询用户详情、修改用户信息等（以自己项目接口文档为准，教师项目示例为认证 4 个 + 用户 6 个，共 10 个）。
   - token 处理：登录接口的响应体里有 token → 添加「后置操作→提取变量」存为环境变量 → 需要登录的接口在 Header（Authorization）中插入 token（Bearer 类型需写成 `Bearer <token>`）。
   - 验证码处理：发送验证码接口响应体 `data.code` 里有验证码 → 提取为变量 → 注册接口的 code 字段引用该变量。
   - 验证通过标准：接口返回成功，且**数据库中对应表出现/变更了数据**（如在 DBever 刷新 t_user 表能看到刚注册的用户）。
   - 测试全部通过后导出 Markdown 接口文档，保存到 `cike/docs/`。
4. **前端↔后端联调（交给 AI 改前端）**：
   - 给 AI 发提示词："根据 <导出的接口文档.md> 完整同步修改前端中有关用户模块的代码"。
   - 修改后在网页上实测：注册 → 发送验证码（开发模式验证码直接显示）→ 登录 → 修改资料 → 退出登录；再刷新数据库确认新增/变更了数据。
   - 前端页面出现真实数据、数据库有对应记录 = 前端、后端、数据库全链路打通。

### 阶段 5：笔记/互动模块联调（后续课程）
- 参照用户模块方法，用 ApiFox 测试笔记模块（发布、查看、删除）与互动模块（点赞、收藏、评论）接口，再同步前端代码。

## 五、概念补充：老师说的"接口"是什么？

**接口（API）＝ 前后端通信的"网址入口"。**

- 前端页面上的每个操作（注册、登录、发笔记、点赞）都不是自己造数据，而是**向后端的一个网址发起"网络请求"**，后端处理完后把结果（JSON 数据）返回给前端渲染。这个"网址 + 请求方式 + 参数"的组合，就是接口。
- 接口由三要素组成：**请求方式**（GET 拿数据 / POST 提交数据 / PUT 修改 / DELETE 删除）、**请求地址**（如 `POST /api/users/register`）、**参数**（注册要传 phone、code、nickname、password；登录返回 token 用于后续鉴权）。
- 老师让你"测接口"，就是用 ApiFox 代替网页，直接向后端发请求，看后端和数据库是否正常：发一个注册请求 → 数据库 t_user 表多一条记录，即接口通了。
- 调后端前先启动 Redis（6379）和 SpringBoot（8080）；接口文档里如果基础地址是 `http://localhost:8080/api/v1`，ApiFox 的前置 URL 要填完整。

**"真正链接一个手机号注册平台吗？" —— 不是。**

- 这是**本地模拟的验证码，不会真的发短信**。课堂里的验证码是后端直接生成、在响应体 `data.code` 里明文返回的（教学靶场直接提示"验证码是 032549"）；自己项目开发模式下前端也直接显示验证码。
- 真实项目要接短信，才需要购买第三方短信服务（阿里云短信 / 腾讯云短信等），要企业资质、申请签名和模板、充钱，每条短信几厘钱。训练营阶段完全不需要，用模拟验证码即可打通全链路。
